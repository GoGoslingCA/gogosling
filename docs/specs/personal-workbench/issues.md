## 1. 本模块要补的展示

| 编号 | 问题 | 影响 | 处理 |
|---|---|---|---|
| K1 | 失败提示分散，没有同时说明保住了什么 | 人会重复开始、重复写回 | 待补。统一成四句：停在哪一环、已经保住什么、没有发生什么、下一步只做一件事 |
| K2 | 同一次操作的几条提示对不上任务名称 | 跨模块时分不清是哪一件事 | 待补。同一次操作带同一时间、环节、任务名称和状态。没有任务时写「尚未创建」。不记录正文、密钥和文件全文 |
| K4 | 排队容易被看成已经在处理 | 人会再发一条 | 排队时说明还没有开始，正在等待执行名额。没有单次占用来源时不编造占用者 |
| K5 | 保存版本、副本、导出、写回共用含糊的「保存失败」 | 人以为原文件已改或已丢 | 失败句必须带动作名称 |
| K9 | 「需要核对」没有写清是预览、确认、写入还是核对 | 文件问题会来回猜 | 待补。文件环节再带一个小步 |
| K10 | 优化失败和任务失败看起来像同一件事 | 人会去任务里找一条并不存在的消息 | 优化单独成环，并写明消息条数不变 |
| K11 | 开始页助手名显示不全 | 人会选错助手 | 选择框悬停显示完整名称。模型和目录在展开后能看到全名 |
| K12 | 正在阅读较早消息时被拉到最新一条 | 人丢失阅读位置 | 离开底部后不再跟随。重新打开一件任务时从最新内容开始 |

K1、K2、K4、K9 是下一步要补的呈现。补齐前不新增按钮。

## 2. 已经有规则、但不能说成已经完全避免的缺口

| 编号 | 问题 | 现在怎么处理 |
|---|---|---|
| K3 | 确认框若只写动作、不写任务名称 | 本模块必须写明任务。写不明就停在确认，不替人选择 |
| K6 | 结果未知时，人仍可能再点一次，从而发出第二条 | 现在先要求核对。彻底避免第二条还不是现版能力 |
| K7 | 不能凭确认档位判断文件有没有改掉 | 只看有没有确认框、状态是不是「已应用」 |
| K8 | 列表和搜索容易被看成已经是全部 | 保持「最多 200 项」和「只搜索已加载任务」 |

## 3. 不在本清单里扩大范围的事

下列事项有过讨论，但不因此变成现版要补的按钮：

- 打开任务就自动继续
- 勾选资料就限制助手只能读这些文件
- 一个项目使用多个助手，或项目之间隔离文件
- 一次写回多个文件
- 电脑合盖后改由云端继续
- 助手再调用另一个助手
- 在预览里编辑办公文件
- 由本应用计算套餐余额
- 消息连接、在线转换、分享链接、获取网页

开始页是否改成更具体的任务入口、发送前先选项目、页脚增加核实说明，仍待单独决定。决定前保持现在的三个示例和现有页脚。
